# Data Provenance

This document records how the current project data files were generated.

## Path Configuration

The repo now uses a lightweight path configuration pattern:

```text
pipeline/config/external_paths.json
pipeline/config/internal_paths.json
```

`pipeline/config/external_paths.json` records absolute external roots and named
artifacts relative to those roots. `internal_paths.json` records named paths
relative to the repository root. `load_paths()` returns a resolver with
`.external(name)` and `.internal(name)` methods. Analytical JSON definitions
are under `pipeline/definitions/`.

## Satellite / Remote-Sensing Data

Satellite data were processed through a mix of scripts and notebooks.

### Raw and Curated Raster Folders

Raw and source-like folders:

```text
sat_data_orig = ...\data\Sat_data_orig
sat_data_raw  = ...\data\Sat_data_raw
```

Curated raster folder:

```text
sat_data_curated = ...\data\Sat_data_curated
```

### Scripted Preprocessing

Known scripted processing:

```text
pipeline/input_preparation/preprocessing/curate_raw_tiffs.py
pipeline/input_preparation/preprocessing/curate_pm_2_5.py
pipeline/input_preparation/preprocessing/curate_oc_bc.py
```

Script responsibilities:

- reproject or verify raw GeoTIFFs in Mollweide
- apply NTL log transform
- derive PM2.5 2010-2012 average and Jan-Feb minus rest-of-year delta
- derive OC/BC 2010-2012 averages and Jan-Feb minus rest-of-year deltas
- write `curation_manifest.json` files into curated raster folders

### Notebook / Earth Engine Processing

ERA5-Land temperature indicators appear to have been generated with:

```text
pipeline/input_preparation/preprocessing/ERA5L_Portugal_Indices_2010_2012_nativegrid.ipynb
```

This notebook uses Google Earth Engine to create:

- heating degree days (`hdd_18`)
- cooling degree days (`cdd_25`)
- extreme heat
- extreme cold

Those outputs were then placed into curated raster folders and used by the index-construction pipeline.

### Rebuild using the existing geometry helpers

`pipeline/input_preparation/preprocessing/build_parishes.py` provides a small command-line
wrapper around the existing CAOP loader and GeoJSON exporter. See
[`pipeline/input_preparation/preprocessing/README.md`](../pipeline/input_preparation/preprocessing/README.md#rebuilding-parish-boundaries)
for the command and source selection.

On 2026-10-31, the five extracted CAOP 2016 polygon layers supplied in
`E:\energy_povert_from_space_data\CAOP_2016_shapefiles` produced
`data/adm_maps/parishes.geojson` (initially built as
`data/parishes.regenerated.geojson`): 2,882 mainland, 156 Azores, and 54 Madeira
parishes. The existing loader repaired a non-closed ring in the Madeira input
using its `pyogrio` fallback and dissolved repeated parish IDs. All 3,092
output geometries were valid, with unique IDs matching the existing GeoJSON.
After aligning rows by `ID`, all geometries passed Shapely's
`equals_exact` comparison at a tolerance of 1e-8 degrees. Only 363 passed
topological equality without a tolerance; the two files are not geometrically
identical at full precision. The original GeoJSON was retained.

The regenerated file contains boundary identifiers and geometry only; the
existing file also contains administrative indicators. This rebuild supports
consistency with the supplied CAOP 2016 layers, but does not establish the
original export history or independently verify the download lineage of the
supplied files. Archive URLs, download dates, and checksums remain to be recorded.

Current configured inputs are `map_dir` under
`E:\energy_povert_from_space_data\data\CAOP_2016_shapefiles` and
`epvi_targets_csv` at `E:\energy_povert_from_space_data\data\epvi_targets.csv`.
Generated outputs use `outputs_root` at `E:\energy_povert_from_space_data\outputs`.
